# 07 · Dependency and Supply Chain

## The split (audit #16) — lean core + optional packs

Kerno 0.2.0 splits its dependencies so a minimal install stays small:

```
pip install kerno             → core only
pip install "kerno[data]"     → + pandas numpy matplotlib scikit-learn scipy openpyxl
pip install "kerno[server]"   → + fastapi uvicorn httpx requests
pip install "kerno[anthropic]" / "kerno[openai]"  → LLM providers
pip install "kerno[timeseries]" "kerno[nlp]" "kerno[graphs]"
         "kerno[documents]" "kerno[sql]" "kerno[security]"  → skill packs
pip install "kerno[all]"      → everything
```

**Core dependency list (4 packages):** `jupyter-client`, `nbformat`,
`ipykernel`, `pyyaml`.

**Why this is safe:** the analytical stack runs *inside* the Jupyter kernel
(skills are kernel-side code strings), not on the host. The host import
graph was audited: no eager pandas/numpy/matplotlib/sklearn/scipy/openpyxl
imports outside kernel-side templates.

## Verified install matrix (fresh venvs)

| Install | Result |
|---|---|
| core only | imports; doctor P1–P10 pass; **full live kernel session** runs; data skills skipped with warning |
| `[data]` | 114 skills load; modules needing other packs (networkx, nltk, openai, requests, sqlalchemy, statsmodels, pdfplumber, docx) skipped with a clear warning |
| `[all]` / `[dev]` | full suite green |

## Skill dependency map (generated from source)

The probe map `_SKILL_DEPS` in `kerno/skills/bootstrap.py` was generated by
scanning every builtin skill's kernel-side imports (not hand-guessed).
`bootstrap(skip_missing_deps=True)` asks the **kernel** in one batched cell
which dependencies are importable, then skips modules with missing deps —
the session never crashes on a lean install.

## Supply-chain posture

| Aspect | Status |
|---|---|
| Build backend | hatchling (standard, pinned in `[build-system]`) |
| Lockfile | Not provided — versions are floor-pinned (`>=`), not locked. Reproducibility manifests record installed versions (`EnvironmentSnapshot`) |
| Pinning | Floor pins only; `requirements-lock` export available (`export_lock`) |
| Optional deps | Never imported on the host unless the pack is installed |
| Vulnerability scanning | Not automated in CI (workflow blocked on permissions) — see `15` |
| SBOM | Not generated |

## Risks and mitigations

- **Transitive drift:** floor pins allow transitive updates. Mitigation:
  reproducibility manifests + environment locks capture actual versions per
  session.
- **Kernel-side packages:** the *kernel* environment may differ from the
  host env. The probe makes missing kernel deps a warning, not a crash.
- **OpenAI/Anthropic SDKs:** treated as trusted transport; both are optional
  extras.
